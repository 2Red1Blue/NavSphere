# Editorial v2 验收与运行协议 · EGP-1

日期：2026-09-08。状态：已定义、未实施、未执行实验；不是生产放行记录。对应 [主设计](editorial-v2-design.md)。本文件集中维护阈值，主设计引用它，避免两个相互漂移的数字来源。

这些数值是首版保守操作政策，不是外部研究证明的最优值。目标是在明确资源边界内提高解释价值，而不是承诺全局最优。调整政策必须创建新版本和新实验，旧失败结果保留，不得用新阈值追认旧批次通过。

## 1. 冻结单位、输入与责任

**验收层**为 `content_type × reading_path × pipeline_fingerprint`。首个目标是 explainer/full；explainer/segmented 单独验证。brief 和 feature 不因解读通过而自动开放。pipeline_fingerprint 绑定实际 writer/reviewer 身份、提示词/Skill、提取器、切分器、摘要器、契约和分发模板版本；功能相同的排版修改不重开模型实验，但仍需前端回归。

A 阶段准备唯一的 `experiment.lock.json`（未来实现产物，不是现在已生成的数据），包含：policy hash、代码/依赖版本、原文哈希、样本集合及顺序、每篇人工 golden、配置与可核验实际模型身份、预算模式和计量口径、v1 基线回执、人工审核人及盲评顺序种子。B 第一次调用前锁定；变更另起 experiment_id。

样本由用户或明确指定的人类编辑在看候选稿之前选定并阅读完整原文。AI 可以辅助定位，但不能替人签署 golden 或人工评分。系统管理员就是执行责任人；未登记人类审核人时只允许影子生成，不允许 D/E/F 发布。正文匿名编号与流程映射由代码封存；评分人不得在评分锁定前查看模型名、路径、token 或耗时，golden 与原文不隐藏。

固定 Psyche 为开发样例。每个验收层再预选 3 篇未用于提示词/规则调优的留出样本：至少覆盖尾部关键结论、反方/限定语、多处数字或样本范围这三种风险，可一篇兼具多项。基线执行不向写手泄露 golden；留出评测后不再把同一篇当作新的未见样本。失败不可删除、替换或择优挑重跑；调优后旧样本成为回归样例，另锁定新留出组。

不新增实验平台。最小实现是一个 policy 文件、一个 append-only experiment/run manifest、一个 fixture runner 与人工评分表；先写在现有工作流产物中，不建单独服务或仪表盘。

## 2. 质量门槛与实验判定

| 条件 | 固定门槛 | 判定与证据 |
|---|---|---|
| 核心要点 | mandatory 全部覆盖；Psyche 为 6/6 | 人工根据冻结原文逐项判定，含对象、范围和条件；只出现关键词算不通过 |
| 已知事实错误/无依据断言 | 未解决数量 0 | 标题、导语、正文、图表/列表、引用和所有分发文案均检查；“0”表示本次审查未发现未修复项，不宣称绝对无错 |
| 引用与重要限定 | 错引、否定反转、关键限定语遗漏均为 0 | 指向原文段落及支持/反对关系；存在争议而未解决则待处理，不按平均分抵消 |
| 解释价值 | 每篇 ≥2/3 | 0=错误/空洞；1=只罗列；2=解释原文至少一条核心论证/机制及相关边界；3=还能清楚解释反方或替代解释。不要求编造新发现 |
| 可读性 | 每篇 ≥2/3 | 0=不可读；1=审计模板/重复明显；2=自然标题、连贯段落、无显著凑字；3=结构精炼、概念解释清楚。人类评分锁定 |
| 协议与权限 | 全部确定性检查通过 | 哈希、输入回执、版本、实际模型身份、来源权限、字节上限、CAS/通知测试均不可豁免 |

baseline 相对错误数量、字数和模型自评分只作诊断，不是发布门槛。任一 mandatory 不通过、证据冲突未解决或审核人无法判断，结果为 NOT_READY，不可自动发布。

Psyche 的六个稳定检查 ID 如下；A 的人类编辑须为每项补齐冻结原文中的段落/字节范围和原值，签署后才是可执行 golden。这里定义判定要求，不伪造已经完成人工标注：

| ID | 必须讲清 | 不可丢的限定 |
|---|---|---|
| PSY-01 | 自我义务与个人偏好、对他人义务的区别 | 不把“不喜欢某习惯”直接等同于道德过错 |
| PSY-02 | 支持与反对自我义务的主要论证 | 两方都解释理由；思想家的主张有归属，不写成已经证实的共识 |
| PSY-03 | 原文如何研究普通人的道德判断 | 区分问卷/情境判断与证明客观道德义务；方法细节只取实际材料 |
| PSY-04 | 后半篇报告的关键结果 | 数字、分母、样本人群、情境范围按原文；不得改写成所有人的结论 |
| PSY-05 | 自我道德化可能提供动力，也可能带来苛责等风险 | 可能性不升级为必然因果；作者讨论与实测结果区分 |
| PSY-06 | 描述性发现与规范性结论之间的距离 | 多数受访者持某种判断，不直接证明客观上应当如此 |

人工冻结的逐项 golden 用于开发、留出、十篇试运行和抽样校准，不假定所有未来文章都有人工答案。F 的新文章由 reviewer 从完整来源先建立重要内容检查表再评成稿，检查表及 source_refs 随 review 持久化，不仅复制 writer 的要点。生产机器门禁要求无未解决的重要遗漏/错误；其可信度由持续人工抽样检验，不把模型自建清单的“100%”冒充人工 golden 通过率。

B 分为开发验证和留出验收：Psyche 经冻结的任务预算完成并达到全部质量条件；每层 3 篇留出必须 3/3 最终质量及资源合格。允许预算内修订，但记录首稿与最终结果。“两次调用”的假设只按首轮原始结果计，不将修订后通过伪装为两次通过；是否适合扩大自动路径还由 §5 的初稿通过率决定。

统一决策顺序：

1. 计量/身份/证据缺失 → INCONCLUSIVE，保持该层自动发布关闭。
2. 质量、资源或可靠性任一失败 → NOT_READY，记录原因，禁止扩容。
3. B 通过 → 只允许进入 D/E 的逐篇人工批准，不直接开放 F。
4. §5 的 F 条件全部通过 → 人工签署该层放行，可启用持续抽样。

缺失计量仍计入任务总数和失败记录，不能通过从分母剔除变成“其余全部通过”。人工因明确数据损坏或测量事故裁定实验无效时，保留原记录，整组重新冻结，不挑选单个失败结果覆盖。

## 3. Reviewer 最低输入与信息保留

### 3.1 full 路径

每次最终审稿必须收到同一冻结的完整正文、全部待公开文本和依据映射。程序验证送入的正文哈希与 SourceDocument 相同；模型理解能力再由 golden 和人工评分检验。源文能够进入 writer 但不能进入 reviewer 时，不属于 full 路径，必须转入 segmented 的独立预算和验收层，或待人工处理。

### 3.2 segmented 路径

1. 按冻结切分器划分原文，正文并集覆盖 100%；重叠段按字节范围去重，首尾段不特殊豁免。边界处上下文可重叠，记录范围，不用固定截字替代语义分段。
2. 每段返回 `segment_id / source_span / claims / qualifiers / counterpoints / empty_reason`。无相关发现也有记录；不能以“相关性低”绕过原文核对。原段顺序、摘要版本与每批输入/输出哈希由核心记录。
3. 与摘录生成相独立的 reviewer 调用逐批接收**全部原文段及对应摘录**，核对丢失、捏造、条件和范围变化，产生 audit receipt。不是只审写手已引用的片段，也不是抽查 20%。角色复用现有 reviewer，不新增常驻 Agent。
4. 所有摘录和 audit receipt 进入最终审稿；超预算时分批检查再合成决定，不以再次压缩的总述替代各批决定。任何未审原段、未解决 issue、截断输出或无法装载的关键片段都阻断自动发布。
5. writer 修稿不改变原文对照回执；reader 摘录或 source 变化使相关 audit 失效，必须重新核对并计入预算。最终审查仍覆盖全文结构性遗漏，不仅是局部引用正确性。

批次采用冻结的顺序贪心装箱：按原段顺序依次加入，在扣除提示、输出预留、安全余量后的 reviewer 上下文上限前停止；不按生成结果择段。单段仍超限则在段落/句边界细分并保留父段映射；不能安全细分或全部原段核对的最少调用数已超剩余任务额度时，调用前返回 budget_insufficient。每批输入必须可哈希重建，最终合成也占调用和上下文预算；装箱参数随切分器版本冻结。

这一做法降低共同摘录盲点，但不保证模型一定识别所有遗漏。**首版 segmented 即使 B 通过也保持逐篇人工批准**；在单独完成 §5 的同层留出和试运行之前不开放自动发布。预算不足以完成全段核对时失败，不暗中缩减核验范围。

### 3.3 信息保留测试与归因

A 冻结至少 6 类 fixture：否定/反例、条件成立范围、相关与因果、数字分母与单位、样本人群/时间、研究结果与作者解释的区别。至少一条关键事实在原 4,000 字符之外，至少一条限定跨分段边界。使用全文路径与强制分段路径处理**相同源文及 golden**，质量标准相同、资源预算分层记录，不能把分段额外调用藏起来。

每个 fixture 的 mandatory proposition 与 qualifier 保留必须 100%，且零新增支持不了的断言；关键限定保留率为“语义正确保留的 mandatory qualifier / 全部 mandatory qualifier”，不使用字符串匹配替代人工/校准判定。再做缺陷注入：删关键尾段、删除否定、去掉样本范围、改数字单位、漏一条 audit receipt；所有这五类固定缺陷样例必须被门禁阻断。人工/模型语义判断的局限记录在回执中，不称为纯机器可证明。

评分前只展示原文与匿名成稿；评分锁定后揭示 `reading_path, segment_count, batch_count, missing_segment_ids, summary_hashes, audit_hashes`。原文未进入阅读批次叫漏读；进入了但摘录丢失叫汇总损失；摘录正确而成稿遗漏叫写作遗漏。允许多原因并存，不凭一个“N 段”推断根因。

## 4. 资源政策：逐任务记账，不用均值掩盖超限

EGP-1 的初版数值如下；此处定义政策，不授权现在执行付费任务：

| 路径 | 自动成稿墙钟上限 | 实际模型调用总数上限 | input+output token 总上限 | API 计费上限 |
|---|---:|---:|---:|---:|
| full 单源 | 240 秒 | 6 | 64,000 且 ≤同源 v1 的 4 倍 | US$1 且 ≤同源 v1 的 4 倍 |
| segmented 单源 | 900 秒 | 24 | 256,000 | US$4 |
| feature 多源 | 未开放 | 不执行 | 不执行 | 不执行 |

同时适用的约束全部成立，取更严格值，不二选一。分段路线不以旧的 4,000 字符短摘要作成本倍率门禁；比较值照常报告，但不得混同为相同工作量。两轮修订是允许的最大轮数，不保证总有余量执行；任何格式修正、重试、fallback、reader、补证、review 与人工触发的模型调用都消耗上表额度。full 初轮恰好两次，不因重试而额外增加“免费第七次”。

墙钟从任务第一次实际自动处理（准备/抓取开始）到审核候选与回执持久化，包含退避、运行期间排队及失败调用；任务重启使用同一 deadline，不重新计时。入队等待、人工等待、发布/通知与全流程总墙钟另列，不宣传 240 秒端到端。实验复用快照时准备时间按实际记录为复用，不伪造一次新抓取；A/B 输入和缓存策略冻结。

`token_total` 使用供应方 input+output 口径；缓存 input 仍计入资源量，计费按真实缓存价；reasoning 若包含在 output 中不可重复加。缺失 usage、无法证实的 adapter 自报身份或未结算的超时调用不能算零，归为 INCONCLUSIVE。每次调用开始前预留最大可能 input/output 与费用，保证剩余额度覆盖调用及日志收尾；无法约束 ACP 内部调用/输出并取得用量时，该适配器不具备自动预算放行资格，可保留影子或人工路径。

API 模式由 A 冻结供应方、币种、地区/缓存/工具计费规则和价目日期，记录估算与实际账单口径；不把现在未知价格填成零。套餐模式将货币倍率明确标为 N/A，使用相同 token、调用和时间门禁；token 是工作量代理，**不是账户剩余额度或账单的换算率**，不制造 token→套餐 quota 换算表。供应方明确报告限流/额度不足时停止，不自动换付费路由。

有可靠同源 v1 基线则 full 使用倍率。v1 执行失败或无可靠 usage 时不得伪造分母或复用别篇平均值：A 明确登记为 absolute-only，使用绝对上限；该实验只能声明绝对可行性，不能声明相对成本通过。这一模式必须在 B 前锁定，看到 B 超倍率后不能改模式。正常新生产文章没有 v1 对照时用绝对上限，不能宣称持续满足逐篇 4 倍；倍率只用于冻结的配对实验。

整个实验另冻结 `max_tasks / max_calls / max_tokens / max_api_cost / max_automatic_wall_time`：由列明的基线、开发、留出和试运行任务逐项按上表保守求和，额外诊断生成默认 0；人工核对耗时单独累计。A 计量准备任务也必须先有清单和绝对预算，未知基线不能无界试跑。总预算由实际 task 清单计算并在人类负责人批准后开始，不用无穷自动“再试一轮”绕过逐任务上限。

若质量通过但资源失败，不降低质量要求、不追认通过：保留内容与成本证据，针对瓶颈优化或提出明确不同的人工/长文路径，再以新政策、新锁定批次重验。

## 5. 人工校准、扩容与失效

### 5.1 首次开放

每个文体×阅读路径独立要求：B 的 3 篇留出全部合格；E 取进入该层的连续 10 篇符合预先纳入条件的新文章，不挑题、不用已有留出稿填充。10 篇均逐篇人工盲评并签署后才发布。最终 **10/10 质量和资源合格，且至少 8/10 首稿质量合格** 才允许 F；full 的这至少 8 篇还必须恰好两次模型调用且无格式修复或 fallback。所有失败留在分母，10 篇未积满保持小范围人工模式。

纳入条件在 A 锁定：来自固定来源/语言列表、显式目标文体、非开发/留出样本、非相同 article_id+source_hash 的重复项；初始阅读路径由固定上下文预算和已有长度信息判定，不能由稿件质量决定。按 entered_at、work_id 稳定排序取前十个任务，在抓取/生成结果出现前登记。仅重复项、已撤回或依法不可处理且在登记前已知的条目可预先排除，并记录理由；登记后抓取失败、长度误判、超预算、身份错误、无法成稿及审核失败全部留在该层分母。转分段或降为简讯产生关联新任务，不能从原层删掉失败记录。无长度信息的来源先标为 segmented，不能看结果后选择更容易通过的层。

初稿是首个 writer 输出及第一次 reviewer 结果，解析失败也算首稿失败。人类必须对初稿与最终稿分别确认关键要点；不能使用模型 approve 代替人类校准。人工做实质文字修正后可另行审核发布，但该样本不算自动候选通过，不能靠人类代写凑到 F。修订次数与资源全部保留。

“首稿质量合格”使用 §2 全部相同质量条件，没有更低的初稿分数线；即使预算内修订后合格，原始初稿失败记录也不改变。

试运行十篇一旦发现影响结论的错误、误引或重复推送，暂停该层队列，追查与修复；未发布稿保持待处理，已发布有问题的稿件按更正/撤回流程处理，不自动批量删稿。修复 pipeline 后原批次保留失败状态，新的留出和十篇验证另起批次。

这些是谨慎上线的操作门槛，不是统计置信度保证，不证明未知文章都可靠；通过 F 只允许该层进入持续抽样，不开启其它文体或绕过逐篇机器门禁。

### 5.2 稳定运行频率与负责人

- 首次开放后的每个自然周（Asia/Shanghai 周一 00:00 至下周一 00:00），设某层当周最终成稿数为 N：N=0 记录 no_output；1≤N<3 全审；N≥3 抽 **max(3, ceil(N×10%))** 篇。分段与全文分别计算，不能只检查容易的全文稿。
- 抽样使用封存种子及文章哈希确定顺序，**抽样池**包含该周所有最终成稿候选（未发布失败另有全量失败统计），不能由写手挑选；下一周二 18:00 前由登记的人类负责人签署。逾期自动暂停该层自动发布，保留生成与待审稿，不阻断已批准内容阅读。
- 用户可指定其他人类编辑；模型不能代签。负责人不在线时系统进入待审状态，不以“尽量自动”取消校准。事实/数字错误、错引/侵权或撤回投诉、标题夸大、重复推送等反馈即时触发复核，不等周抽样；确认重大质量错误后按 §5.1 的暂停/修复流程处理。
- 改变实际模型、写作/审查 prompt、提取/切分/摘要逻辑或证据/派生契约时，立即关闭受影响层自动发布，重跑固定黄金回归与该层的新留出/试运行。只有经差异检查确认纯排版且不改变审定文字的改动才免于内容重验。

### 5.3 留痕而不新增平台

沿用工作流事件记录 `policy_hash, experiment_id, stratum, sample_id, initial/final publication_hash, coverage_decisions, source_audit_hashes, usage, deadlines, human_reviewer, blind_score_locked_at, unblinded_at, decision, reason`。这些是有限的验收记录，不是新增公开 D1 列，也不是隐藏推理日志。终局决定只能由核心按规则计算并附人类签署，不能由模型修改阈值或宣布“实验通过”。

## 6. 迁移失败恢复与演练

迁移前停止所有写入者（调度、回调、手工管理入口），等待/终止在途写入并记录水位；取得 SQLite 一致备份及备份哈希，在隔离副本执行完整性检查。不要在 WAL 活跃时只拷贝主 db 文件冒充一致备份。停止写入与确认备份完成后才允许重建；备份有问题则原库保持不变、退出迁移。

| 故障位置 | 恢复动作 | 允许恢复调度的证据 |
|---|---|---|
| 事务开始前 | 不动原库，修复准备步骤 | 原 v1 schema/数据哈希、无在途写入损坏、v1 dry-run 通过 |
| 事务中，未提交 | ROLLBACK；进程崩溃后确认 SQLite 恢复结果 | integrity_check=ok、foreign_key_check 无行；工作项/事件/草稿/审批/推送回执的行数及规范化摘要与水位一致 |
| 已提交，尚未重新开放写入 | 保留失败新库副本，在停写状态恢复经验证备份，运行 v1 兼容检查 | 前述一致性 + v1 代码只读恢复/排队 dry-run；禁实际 publish/notify |
| 已开放写入后才发现问题 | 再次停写，保存当前库及 WAL 的一致快照；禁止旧备份直接覆盖；对账新增/变化工作项并采用经审查的前向修复或带增量恢复 | 新旧水位和新增记录全部可解释；本地与远端已发布 revision/回执对账，无重复首发；人工批准后才恢复 |

任何检查失败保持调度关闭并报错，不自动“尝试 v1 启动”。本地回滚不撤销已发生的远端发布/推送：存在 publish_unknown/delivery_unknown 时先对账，不重新发送。

**备份准入与版本标记（2026-09-09 迁移演练与实现回灌）**：

- 备份准入 = integrity_check **加** 与源在线状态比对（行数、写入水位、规范化摘要）。仅 integrity_check 不足以识别"陈旧但自洽"的冷拷贝（WAL 活跃时可能仍为 ok）与落在空闲区域的轻微软损坏。
- schema 版本标记：`editorial_schema_migrations` 迁移注册表（append-only trigger）为**权威**；`PRAGMA user_version` 仅在同一事务内镜像最高版本号作为只读快速信号。v1 库 = registry 空。
- v1 dry-run 最小查询集（只读验收命令）：只读打开、排队查询（queued 行数/ids）、publish_unknown/delivery_unknown 计数、succeeded_deliveries、integrity_check、foreign_key_check、user_version/registry、前后文件哈希一致（file_unchanged）。
- 前向修复对账记录落盘格式：`kind/recorded_at/target/old_watermark/new_watermark/row_count_deltas/work_items_delta/new_records[{work_id,article_id,state,generation_key,created_at}]/explainable/old_backup_overwrite_refused/decision/human_approval_required_to_resume/scheduler_resumed:false`。
- 迁移演练必须调用真实 `EditorialWorkflowStore`（有效 16-hex 首发、同源去重、显式 rewrite、并发 enqueue、CAS、撤回、通知跳过），不得用裸 SQL 插入虚构 work_id 充当恢复证明。

实施验收必须在隔离副本注入四个故障：建表后、复制中、提交后未开写、开写并新增一条工作项后。验证前面三个能完整回到 v1；第四个必须拒绝覆盖恢复并保住新记录。另测备份损坏和模拟 WAL 活跃备份，验证拒绝不一致备份。保存演练日志、库版本/哈希、行数/历史摘要、完整性结果和无外部副作用证明。演练通过前禁止生产表重建。

## 7. 最小落地顺序与完成定义

1. A：冻结 v1 fixtures，制作 golden/样本清单和 policy/experiment lock；核实实际模型身份与计量能力。不建新运行时。
2. B：先 full 路径影子验证；segmented 的对照审查和信息损失 fixture 独立实现，不阻塞 full 的开发，但不提前开放 segmented 自动发布。
3. C/D：Reader/API 双读、恢复演练、Psyche 人工签署后 CAS 修订且不推送。
4. E/F：按固定留出、连续十篇与周抽样逐层放行；任何规则不满足留在原层。

“方案补齐”表示上述规则和失败路径已明确；“实现完成”要求代码和 fixture 通过；“质量验证通过”要求实际实验及人类签署；“上线完成”还要求生产读回与推送核对。四者不相互替代。EGP-1 尚无实验、实际花费或人类评分结果，本次不得将其标为运行通过。
