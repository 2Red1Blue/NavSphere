# Editorial v2：从短摘要流水线到有深度的文章生产

日期：2026-09-08。状态：设计提案，尚未实施或上线。本次不调整全局模型路由、凭证、生产数据或推送策略。

放行规则补全于 2026-09-08：[验收与运行协议 EGP-1](editorial-v2-acceptance-protocol.md) 是阈值、人工校准和恢复条件的唯一规则来源。下面保留架构说明，不重复定义数值；协议仍待实现，文档完成不等于实验通过。

## 1. 核心决策

保留 Python Content Core、SQLite 持久化工作流、Hermes 调度、ACP Agent 接口和 NavSphere/Cloudflare 发布端。重构内容契约，不迁移整套运行时，也不为每篇文章堆叠多个 Agent。

目标不是把 400 字扩成 2,000 字，而是让读者读到原文的核心问题、论证、重要研究结果、适用条件和真正有价值的解释。完整阅读是前提；自然表达、重要遗漏审查和版本一致性共同构成质量保障。

第一阶段只实现单源解读与简讯；多源专题共用数据契约，等前两类验收后再开放研究调度。

### 已核验的问题

| 当前实现 | 直接后果 | 对应改造 |
|---|---|---|
| `scripts/source_evidence.py` 固定取前 4,000 字符 | 后半篇的研究与结论没有进入写手和审稿上下文 | 完整快照、输入预算、超长文分段覆盖 |
| `scripts/news_brief.py` 固定 facts/analysis/caveats，总长最多 1,400 字符 | 所有体裁都被压成短新闻 | 文体路由 + 自然正文 v2 |
| `style-guide/ai-news-editorial.md` 目标 300–600 字 | “写得短”是在遵守现有任务，不是模型无能力 | 分体裁写作规范 |
| 只审已写出的断言，缺少全篇重要遗漏检查 | 简短但遗漏核心内容的文章也会通过 | 全文/覆盖表对照审稿 |
| writer envelope 重建当前 prompt 进行哈希校验 | 直接替换全局版本可能使旧回执失效 | 不可变版本注册与分版本校验 |
| D1 `publication_json` 上限 24 KiB；请求与 manifest 也有独立上限 | 只增加写手字数会在发布端失败 | 同时计量序列化大小并保留协议限额 |

Psyche 示例保存的来源正文约 10,173 字符，目前证据包只包含前 4,000 字符。现稿既缺少后半部分研究，也把“材料没给到模型”误写成“文章没有经验数据”。这不是前端少渲染了一段。

## 2. 内容产品与读者体验

### 2.1 三种文体，不是三套系统

| 文体 | 适用内容 | 读者应得到什么 | 默认执行策略 |
|---|---|---|---|
| 简讯 `brief` | 产品发布、事件更新、单一事实 | 发生了什么、有什么影响、关键条件 | 写手 + 审稿 |
| 原文解读 `explainer` | 观点长文、论文解读、方法论 | 问题、论证、方法/结果、反例或边界 | 预算内全文写作 + 审稿 |
| 专题 `feature` | 多方争议、技术路线比较、跨来源趋势 | 子问题、不同证据、异同与综合判断 | 有限研究 → 分节或一次综合 → 审稿 |

建议试运行的中文篇幅：简讯 200–500 字、解读 1,000–2,000 字、专题 2,000–4,000 字。这些是编辑预算，不是最低字数门禁、行业标准或已验证最佳值。材料不足时降级为明确标识的简讯；不能凭空扩写，也不能以“解读”标题包装未完成的短摘。

不按网站域名硬分体裁。输入显式指定优先；否则结合来源结构、文章问题和现有内容类型提出建议，代码校验后选择。不可把“健康领域”自动当成医疗建议，也不可把作者观点自动升级为新闻事实。

### 2.2 标题与摘要

- 新 v2 文章显示审定后的 `article.title`，而不是原始抓取标题或内部审核标签。
- `original_title` 留作来源书目信息；v1 继续使用既有兼容显示规则。不能让旧的“原始标题优先”辅助函数覆盖 v2 已审定标题。
- 不使用“整理帖称”“依据材料整理”等流水线措辞；但证据仅来自社交帖时，标题仍须保留实质限定，或放弃发布未经核实的排名结论。去掉难听措辞不等于去掉不确定性。
- 列表摘要、文章导语和飞书文案围绕同一正文生成，禁止各自重新解读原始材料。
- 评分和版本号不占读者首屏；有意义的来源署名、发布日期、更正说明保留。

### 2.3 文章页设计

保留现有站点视觉框架，不做第二次全站换肤。文章阅读区使用安静背景、高对比正文，赛博元素只留在导航、细线与交互反馈中；正文背后不放扫描线、闪烁字或持续粒子。

```text
返回列表                                       阅读进度

原文解读 · 心理与哲学 · 预计阅读时间
不善待自己，是一种道德过错吗？
一段提出问题的导语，而不是重复标题
来源：Psyche · 作者署名                 查看原文 ↗

正文：真实论题的小标题和自然段       [桌面宽屏：本篇目录]
   为什么对自己也会感到内疚
   ……
   需要时出现轻量来源编号 [1]

相关来源 / 有实质变化时的更正说明
```

上述标题与小标题是设计示意，不是已经审核的新成稿。

建议排版：正文最大宽度 720 px、17–18 px 字号、约 1.8 行高；文章标题桌面约 32–40 px、手机 26–30 px，不使用大幅海报字体。列表标题 18–22 px，摘要比标题弱一级。具体值需浏览器验证长中文标题、手机换行和无障碍缩放。

动态交互只做阅读进度、目录当前节提示、来源展开、返回原阅读位置；尊重 reduced-motion，交互可用键盘，移动端目录折叠。不把正文藏在默认关闭的“展开导读”中，不用逐字动画拖慢阅读。

引用显示自然的 [1] 或来源名，同一段同一来源不反复堆标记；不显示 E1、内部断言类型、审稿分数。原文是来源而不是本系统全文转载授权；仍需检查署名、引用长度和授权边界。

“查看原文”必须使用经来源解析与安全检查确定的上游正文 URL；AIHOT 聚合页另列为发现来源。无法确认上游时明确显示可用来源，不猜测 URL，不把不可访问的全文伪装成已读。

## 3. 总体流程：语义阶段与模型调用分开

```text
发现文章 → 安全抓取 → 不可变全文快照 → 文体与上下文预算
                                      │
                  ┌───────────────────┴─────────────────┐
                  │预算内单篇                           │超长/多源
                  │全文 + 编辑任务                      │分段覆盖/有限补充研究
                  └───────────────────┬─────────────────┘
                                      ↓
                      写手：自然正文 + 依据映射 + 简短编辑摘要
                                      ↓
                      正文摘要字段 → 确定性网站/飞书投影
                                      ↓
                      审稿：事实 + 重要遗漏 + 表达 + 派生文案
                           │通过                 │失败
                           ↓                     └→ 定向修订/补证/人工处理
                      代码发布门禁
                           ↓
                      版本化发布 → 读回核对 → 幂等推送
```

默认单篇路径是两次主要模型调用：写手、审稿。文体、读取、哈希、预算、引用解析、卡片投影、发布和通知不是各起一个 Agent。初稿同时返回简短编辑摘要和正文，不增加固定的“思考 Agent”。

“两次”只描述预算内全文路径的无重试、无修订首轮。重试和修订占用同一任务预算；分段路径另行验收，不能把 reader 或分段核对移出统计来声称仍是两次调用。

超长材料才新增 reader 调用；多源专题才新增 planner/research 调用。模型能力可以通过 ACP 替换，是否调用由任务复杂度和证据缺口决定。

## 4. 证据与完整阅读

### 4.1 SourceDocument v2

完整网页、提取正文、抓取回执继续存放在私有 `source-evidence/` 内容存储，不上传原始全文到公开 D1。新增版本化文档索引：

```json
{
  "schema_version": 2,
  "document_id": "doc_<content-addressed-id>",
  "source_url": "https://example.org/article",
  "title": "来源标题",
  "text_sha256": "<64-hex>",
  "extractor_version": "<pinned-version>",
  "segments": [
    {"id": "s01", "start_byte": 0, "end_byte": 932, "text_sha256": "<64-hex>"}
  ]
}
```

示例是字段草案，不是当前有效 API 请求。抓取时间、响应摘要、重定向链和来源归属保留在现有 capture receipt，不在每个片段重复。

分段按标题和段落，必要时拆超长段落。位移采用冻结后的 UTF-8 正文 **字节范围 `[start,end)`**，代码验证落在字符边界；不能混用 Python 字符数与 JavaScript UTF-16 索引。任何规范化发生在快照哈希前，之后不重新整理正文。引用绑定文档哈希、片段 ID 与字节范围；重抓取生成新快照，不悄悄替换旧证据。

### 4.2 两种读取路径

**能容纳：传完整正文。** 计算系统提示、编辑规范、材料、输出预留和安全余量的总 token 预算；不能仅看文件字符数。对该篇 Psyche 文本，优先验证全文进入现有模型上下文，不先做摘要压缩。

**超预算：分段覆盖后再写。** 所有正文段均被分配到阅读批次；每批提取相关论点、数字、条件、反例与可引用范围，保留全文可回查指针。合成写作任务时携带全篇覆盖摘要和相关原文片段；审稿遇到争议可请求核心重新装载原段。不得只检索开头或只用相似度最高的若干片段。

覆盖状态严格区分：`available`（已抓到）、`provided`（已送进一次成功调用）、`summarized`（有结构化摘录）、`used`（稿件实际引用）、`excluded`（与选题无关且附理由）。送入不证明理解，模型声称“全文读完”不是覆盖凭证。

程序可验证段落分配、范围与引用存在；“哪些内容重要”由模型评价和样例人工基准共同校准，不能包装成客观准确率。抽取疑似登录页、正文异常短或章节缺失时阻断解读路线，必要时作为有限信息简讯处理。

分段路径新增两个必要条件：每个原段必须有摘录或明确的空记录；独立于摘录生成的审稿调用必须逐批看到全部原文并对照摘录，检查数字、否定、条件、样本范围及反例。仅“分配完所有段落”或记录“N 段汇总”不构成信息保留验收。详见协议 §3 的原文对照回执与黄金样例；预算不足以核对全部原段时不放行自动解读。

### 4.3 来源与资料缺口

发现 URL 与上游原文、观点文章与其引用论文分开记录。读过 Psyche 并不等于读过其引用的原始研究。要论证研究方法或样本外推且材料不足时，才请求定位论文；找不到就保留明确边界，不能补写模型记忆中的数字。

研究员只提交结构化查询、候选 URL 和所需片段。核心执行安全抓取：复用 SSRF、防私网/本机/元数据地址、每次重定向验证、体积/类型/超时限制。网页内指令全部视为不可信内容，不可改变系统提示、权限或发布门禁。

## 5. 写手与 Think 的适配

把 Think 的可用方法改写为版本化编辑规范：找出核心问题；区分事实、作者主张与本稿解释；检查相反理由；识别关键缺口；判断是否足以成稿。**不把整个通用 Skill 原样拼进每一轮提示。**

首版为固定、可审计的编辑规范文本，运行时不自动下载 Skill，也不给写手文件系统和 shell 权限。既有 ACP 无工具模式可继续工作。需要片段回查时，由结构化请求交给核心代取，不要求模型直接浏览私有目录。

私有 `EditorialNote` 只保存简洁工作产物：读者问题、拟定章节、关键来源、未解决问题及采取的处理方式。它不是隐藏推理记录，也不要求逐步内心独白。后台可以显示“读了哪些材料、为何未发布、哪些段落被修订”，不公开原始思考流。

其中阅读路径、原段数量、批次数、输入/摘录/核对哈希及缺失记录由核心从执行回执写入，模型无权自报覆盖状态。人工先对匿名正文及原文评分，锁定评分后才揭示这些流程字段做漏读/汇总损失归因，避免破坏盲评。

写手返回 `draft + evidence_links + editorial_note`。内容不足返回 `needs_evidence` 和缺口，不编造一篇合规假稿。格式错误最多一次受预算约束的修正；截断 JSON 不能自动修补后送发布。

评估 Think 增益时，控制相同来源、实际模型与篇幅预算，对比“无编辑规划/内嵌简短规划”；独立 planner 调用作为后续选项。先证明质量增益，再决定是否增加固定成本。

## 6. 数据契约与存储

### 6.1 PublicArticle v2

```json
{
  "schema_version": 2,
  "renderer_version": "editorial-v2",
  "article_id": "5c35ffca30a49a9a",
  "content_type": "explainer",
  "article": {
    "title": "不善待自己，是一种道德过错吗？",
    "deck": "这里是一段经过审核的导语。",
    "sections": [
      {
        "id": "sec_01",
        "heading": "为什么对自己也会感到内疚",
        "blocks": [
          {"id": "b_01", "type": "paragraph", "text": "这里是正文。", "source_ids": ["src_01"]}
        ]
      }
    ]
  },
  "sources": [{"id": "src_01", "title": "原文标题", "url": "https://example.org/article"}]
}
```

示例省略现有 source provenance、证据摘要及审核绑定字段，不可直接作为提交请求。首版仅支持 paragraph/list/quote 及经过校验的少量行内强调，不支持任意 HTML、脚本或模型提供的组件。渲染器从结构生成视图，不让模型同时输出另一份可漂移的 Markdown 正文。

标题、导语、节标题、列表项、引用、来源展示文字以及分发文案均纳入审查范围。正文块 ID 在修订中保持对应关系，但文本哈希变化立即使旧审查决定失效；删改块也必须更新覆盖和派生摘要，不能复用旧签名。

### 6.2 公私分离与字段必要性

| 数据 | 必要性 | 存储与用途 |
|---|---|---|
| 全文快照、来源回执、版本哈希 | 必需 | 私有内容存储，复现与回查 |
| 段落索引与输入覆盖记录 | 必需 | 私有产物，定位缺失与预算降级 |
| 成稿、依据映射、审查与发布回执 | 必需 | SQLite 元数据 + 私有不可变产物；公开投影进 D1 |
| 文体、父版本、目标远端 revision | 必需 | 决定执行和 CAS 更新，不能并入普通标签 |
| 简短编辑说明、大纲 | 条件性 | 专题/复杂解读使用；不要求每篇多一个模型调用 |
| 向量数据库、知识图谱、独立规划服务 | 首版不需要 | 当前规模下先使用原文与段落索引 |
| 原始隐藏推理、每个角色一张表、重复全文列 | 不需要 | 不保存、不新建 |

不新增五套“Agent 数据库”。优先扩展现有工作项的版本化 JSON 与历史产物记录；只有需要检索、唯一约束或事务控制的字段单独加列。

建议工作项增加 `pipeline_version`、`generation_key`、`supersedes_work_id`、`target_revision`；其中父工作项和目标版本仅更新已发布文章时存在。`generation_key` 由 article_id、源快照摘要、编辑规范版本、操作类型、目标版本及显式重写代次构造，唯一约束防止重试重复建单。模型变更不自动重发全部文章，重写必须显式建新代次。

当前 SQLite 有 `UNIQUE(article_id, source_snapshot_sha256)`，enqueue 查询也使用这两个字段。只新增 generation_key 不会解除旧约束，仍无法同源重写。实施时需要受控表重建：暂停工作流写入、取得一致备份、保留所有 work_id 与历史外键、为旧工作项回填 legacy generation key、替换旧唯一约束及 enqueue 查找规则、验证 foreign_key_check/integrity_check 后恢复调度。旧接口的幂等语义保持不变，新 rewrite 操作显式指定代次；不能仅删除唯一约束让并发首发建出多个任务。

失败恢复按协议 §6 分支处理：提交前优先事务回滚；提交后尚未恢复写入，可恢复已验证备份并验证 v1 兼容性；已恢复写入则禁止用旧备份覆盖新增数据，先停写、保存现状并对账。校验未通过时保持调度关闭。迁移日志、库一致性检查、历史外键/回执摘要和 v1 dry-run 是恢复证据，不以“进程启动成功”代替恢复验收。

### 6.3 容量与 D1

首版保留当前 24 KiB publication、32 KiB manifest、48 KiB request 上限，以 UTF-8 序列化后的真实字节计量。自然正文不必立即增加 D1 表：现有 publication_json 可承载 v2，前提是 Reader、服务端与 Python 都理解新版本。

完整网页、审稿长报告和所有草稿历史不进 D1。私有证据映射可以详细，公开来源与提交用审核摘要保持紧凑；仍需覆盖所有公开文字，不能为了压体积删审核项。超限回到编辑压缩或人工处理，绝不静默截断已审稿正文。

若真实样例证明专题需要更大额度，再以独立迁移同步提升 D1 CHECK、Python/TS validator、HTTP 读取上限和测试，先算存量与增长。不要先做一套冷热存储系统来解决尚未出现的 24 KiB 问题。

沿用容量与访问价值驱动的归档方向，不把“30 天”写成正文永久生存期。实施前核对当前维护 handler：项目规范指出部分路径仍传固定 30 天，不能把审计参数变化当成生产归档已改变。

优先归档大体积、低访问的旧来源/旧正文，保留稳定 URL、文章索引、权限/撤回控制、来源与内容摘要。迁移顺序为复制 → 校验哈希 → 验证可读 → 切换指针 → 释放热副本。归档失败不删除热数据。沿用已有存储边界；如计划启用额外 Cloudflare 产品，另行核验免费额度和账户配置。

容量报警基于实际数据库物理大小、增长率与写入预算，阈值做可配置政策；本次不宣称已测出可容纳多少篇文章，也不重新承诺账户免费额度。公开详情仍在读正文前后检查撤回权限，缓存不能绕过撤回。

## 7. 审稿：检查错误，也检查漏掉了什么

explainer 的审稿最低输入是硬要求：预算内收到冻结全文、全部公开文案和依据映射；超预算收到全部逐段阅读记录、全部原段对照核验回执以及可回查原文，不能只收到再次合并的覆盖摘要。记录仍超预算时分批审查并合成最终决定，不能丢弃记录。缺任何原段核验、影响结论的限定语或核验预算时返回 needs_evidence/manual_review。共同摘录仍可能形成共同盲点，所以必须另做逐批原文对照及人工基准验收；模型自评不替代它们。

一次整体审稿输出四个维度，避免固定双模型多轮逐段串行审稿：

1. **事实支持**：人名、数字、比较对象、时间、限定语、来源归属是否被材料支持。
2. **重要遗漏**：文章核心问题、关键研究、反方理由和影响结论的局限是否缺失。
3. **解释质量**：是否说明“为什么”，是否混淆相关与因果、描述事实与规范判断，是否重复凑字。
4. **读者表达**：标题是否准确自然、段落是否连贯、摘要是否夸大正文。

`ReviewReport v2` 的 issue 目标可为 `document`、`coverage_requirement` 或 `block_id`。当前仅允许 existing path 的设计无法表达“缺少整个研究结果章节”，必须扩展。字段建议 `severity`、`code`、`target`、`evidence_refs`、`requested_change`；具体问题可定位，避免只输出综合分。

审稿建议为 approve / revise / needs_evidence / reject。是否允许发布仍由代码控制：契约、哈希、来源、安全、实际模型身份、严重未解决问题、授权和版本前提全部满足才放行。医药/金融等高风险建议与强事实争议可以升级人工审查，不将全领域文章都按同一敏感模板处理。

默认最多两轮内容修订，与现有持久化上限保持一致；每轮要有具体问题与修改差异。输出来回重复或预算耗尽进入待处理，不无限“写手↔审稿”。不设置 0–100 总分作为唯一发布条件，也不公开机械总分。

## 8. ACP、模型身份与执行预算

`AgentBus` 继续作为唯一模型调用入口，逻辑角色 writer/reviewer/reader/researcher 可使用已配置 ACP 或 HTTP 后端。首版只增加契约，不为每个角色绑定一个常驻进程。

- 保留实际 provider、model、adapter 版本、prompt/policy hash、input/output hash、耗时、usage 和状态；字段未知记录 unknown，不把配置值伪装成实际值。
- writer 与 reviewer 至少是不同实际模型的独立调用；不能仅比较路由名称。配置要求 Claude 而响应身份是其他模型时视为身份不匹配，不能标记 Claude 审查通过。
- 不建议此刻把“换成更大模型”作为首要措施。先固定当前已验证模型组合做同源 A/B；模型升级作为独立变量。
- 角色运行无发布、数据库、凭证和任意 shell 权限。系统控制的 fetch/publish/notify 不接受模型伪造的授权回执。
- 外部调用失败采用有限重试与退避；鉴权或模型身份错误不盲目重试，不静默降级审核标准。

预算按任务执行全程计算，而非给每一步重新开始计时：

`可用材料 token = 模型上下文限制 − 系统/Skill/协议 token − 输出预留 − 安全余量`

每个模型配置独立上下文、输出与超时能力表；估算缺乏精确 tokenizer 时使用保守边界并记录不确定性。超限走显式分段，不静默截前缀。自动成稿的逐任务时间、调用、token 与货币预算按协议 §4 执行，取所有适用上限中更严格者；不保证每篇都能在预算内通过。人工等待与发布/通知另记墙钟时间，不把自动成稿时限宣传为端到端时限。

多源专题保持关闭；开放时必须登记独立文体/阅读路径及冻结预算，不借用单源测试结果。预算耗尽保留已完成产物并待处理，不能发布未审完的稿件。记录时间分解，区分排队、抓取、首 token、生成、工具等待和重试，解决“慢”时先看真实瓶颈。

## 9. 摘要、发布和飞书一致性

首版不增加独立“飞书写手”。写手给出正文与精短摘要字段；摘要必须能映射到正文块。代码投影出网站列表和飞书卡片，再与正文一起审核并绑定版本。可先直接复用 deck，不要求额外的模型摘要调用。

若后续需要正文审定后再调用模型改写营销文案，该结果必须再审查；不能因为输入正文已批准，就默认派生新标题没有夸大。

正文哈希不包含回指自己的派生字段，避免循环摘要：先计算 canonical article hash，再构建绑定该 hash 的 distribution 对象，最后对完整 publication/manifest 签名。任何发布后标题或摘要改动都形成新 publication，不改 CDN 上的旁路文案。

飞书卡片包含审定标题、简短摘要、站内阅读全文、上游原文；成功发布并读回 article_id/revision/hash 匹配后才允许发送。投影模板版本进入通知幂等键，例如 article_id + revision + channel + delivery_kind；网络超时后的 unknown 不当成失败直接再发。

不能向用户承诺 webhook exactly-once：本地唯一键能避免正常重复，外部成功但响应丢失仍可能无法确认。保持现有 unknown 处理，先对账/人工决定，避免为了“保证送达”自动重复推送。

本次旧稿改写默认 `notify=false`；确需更新通知才显式生成更正卡片。通知时再次确认当前版本与撤回状态，不能发送已被新版本替代或已撤回的排队卡片。

持久化 `delivery_disposition=required|skipped` 及原因。修订禁推时停在 published 且 disposition=skipped，任务调度按“发布完成且推送跳过”判定完成；不能伪造 notified 成功回执，也不能让通用 published 扫描器再次将其加入待推送。需要通知时仍使用现有 delivery_pending/unknown/notified 路径。

## 10. 版本兼容与已发布文章重写

### 10.1 分层版本，不重解释历史

分别版本化 source capture、evidence packet、writer envelope、review report、publication/renderer。旧 v1 prompt 与 validator 保留为不可变实现，按 envelope 中的版本分派；不要让 v1 校验器调用“当前最新 prompt”。

版本号不能笼统地全部改成 2：当前 capture receipt 已有 schema 1/2，且 schema 2 仍描述前缀选段，所以完整读取回执应分配 **capture receipt v3**；evidence packet、writer envelope、publication 则从各自 v1 扩为 v2。新增文档索引是独立契约；文中的 SourceDocument v2 是与新证据体系对应的草案名称，不覆盖历史 receipt v2。实施前为每一种契约明确注册表与 fixture，而不是共用一个全局 VERSION。

新 v2 envelope 包含实际输入摘要、使用的规范原文/摘要、输出哈希和模型回执。Python/TypeScript 使用共同黄金 fixture 验证规范化 JSON；尤其测试中文、emoji、换行、组合字符、数字边界、重复 key 和非法字段。严格 JSON 的旧规则不因 v2 放松。

发布协议仍保留代码签署的 manifest/attestation 和 expected_state/expected_revision。v2 可增加字段，但不能把模型 review JSON 当发布权限。读端遇到未知版本显式拒绝或显示可理解的不可用状态，不降级渲染一部分冒充完整文章。

### 10.2 更新不能靠重新 enqueue 旧工作项

```text
旧 work（notified，保持不可变）
  └─ 显式 rewrite 请求 → 新 work（关联旧 work + 目标 revision）
       → 新证据/草稿/审稿 → 重新读取线上版本
       → 审批绑定 expected_state=published、expected_revision=N
       → CAS 成功写入 N+1 → 读回验证 → 默认不通知
```

source/article identity 不变，站内 URL 不变；不要修改源快照制造“新来源”，也不要删除旧终态来绕过去重。当前 auto-release 只允许 absent 的策略须增加明确的编辑更新路径；没有更新授权时停在待批准，不能复用首发批准。

CAS 冲突重新读取后提交新的候选/审批，不把 expected_revision 自动加一重试。发布结果 unknown 时先读取远端 hash：相同说明已成功；不同则冲突或待调查，不重复覆盖。

回滚内容也是新 revision 引用先前批准的正文，保留审计历史；不倒退远端 revision。撤回优先于恢复/更新；撤回后的恢复需要单独明确授权。

## 12. 验收样例与测试

### 12.1 Psyche 样例验收

人工从完整来源建立六项要点清单：

1. 对自己的义务与个人偏好有什么不同。
2. 支持与反对自我义务的主要理由。
3. 作者如何研究普通人的道德判断。
4. 原文报告的关键结果、样本人群与限定范围。
5. 自我道德化可能带来的动力，以及苛责、内疚等风险。
6. 描述性的问卷结果为什么不能直接证明“客观上存在某种道德义务”。

六项用于检验该文遗漏，不是所有文章的固定模板。尤其检查原先 4,000 字符之外的调查部分：不能再说原文完全没有经验材料，也不能把特定样本结果写成全人类共识。未取得论文全文时，清楚归因于原文的转述，不虚构独立论文核验。

同一来源运行 v1 基线和 v2 候选，人工盲看准确性、关键点、解释价值、自然表达和冗余；同时记录真实模型、输入输出 token、调用次数、耗时和费用。小样本用于发现缺陷，不宣称统计上证明了某个模型或流程全面更优。

具体判定见协议 §2/§5：Psyche 六项必须 6/6 且条件正确；候选稿已发现的无依据断言、错误引用和重要遗漏必须归零，不能只要求“不劣于 v1”。每个待开放文体×阅读路径另设三篇未用于调优的留出样本，再经连续十篇人工审核的试运行；扩容与周期抽样有固定频率、责任人、失败和逾期处理。

### 12.2 必须覆盖的自动化测试

- 关键结论仅在第 4,001 字符之后、全文超上下文、提取到登录页、段落切分跨 emoji、同源重抓正文改变。
- 标题正确但正文捏造数字；正文正确但摘要夸大；整节重要研究漏写；无证据来源引用；重复章节；quote 超编辑引用政策。
- 未知契约/renderer/prompt 版本拒绝；v1 历史 fixture 完整通过；Python/TS 字节哈希一致。
- 每个公开文字节点都有审核处理；修改已审正文一字、重排语义节点、修改标题/引用/摘要使旧审批失效。
- UTF-8 public/manifest/request 在上限内、刚好等于上限、超一字节，超限不产生残缺发布。
- writer/reviewer 相同实际模型、配置 Claude 但实际其他模型、身份缺失、超时、截断 JSON、连续失败和人工接管。
- 已通知文章新建修订不重复首发；重试建单唯一；CAS 冲突；发布成功响应丢失；旧卡片排队后正文撤回；webhook unknown 不盲目补发。
- v1/v2 详情、列表、日报、主题页标题与摘要一致；手机正文可读、目录键盘可用、reduced-motion、长标题和缩放无溢出。
- 冷正文取回失败返回可重试错误；读正文期间撤回阻止展示；归档失败保留热副本。
